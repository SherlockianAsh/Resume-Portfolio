Public edition. The private casebook holds the exhibits; the samples never left the lab. Every attacker address below is defanged (hxxps, [.]).

Ringkasan (BM)

Seorang pengguna Threads bertanya tentang satu "human verification" yang menyuruh pengguna Mac buka Terminal dan paste satu command. Itu scam. Kami ambil ketiga-tiga layer ke dalam makmal terasing dan membedahnya dalam 2 jam 6 minit tanpa menjalankan satu layer pun. The dissection

1. Passive first

DNS through a public resolver, the registration record and certificate transparency. Both domains were four days old and registered 22 seconds apart at the same registrar, behind Cloudflare.

2. Capture without being seen, store without being run

Each layer was fetched through Tor with the User-Agent the real stage would send, written read-only, and hashed. A VM snapshot preceded each stage.

3. Layer 1: strings

No address or keyword is readable. 303 small builders produce the strings at run time. Each self-contained builder was cut out and evaluated alone in an empty Node vm context, as an unprivileged user with no network. Result: 188 unique strings, among them four lists: 22 virtual-machine vendor words, 16 time zones, 12 country codes and 12 language names (RU, BY, KZ, AM, AZ, KG, MD, TJ, UZ, TM, GE, UA).

4. Layer 1: the key

Eight functions each return one of two 8-byte tokens. They ask about: the hypervisor flag, hardware strings, System Integrity Protection, the AppleSMC entry, a debugger, the locale, the keyboard layout, the time zone. The tokens are hashed into the key for three encrypted blobs, each guarded by a 16-byte integrity check.

Two outcomes per check means the answers can be enumerated, and the loader's own integrity check says which combination is right. 683 tries. The combination that opens it is "an ordinary Mac outside those twelve countries".

5. Layer 2: the dropper

It writes the download to ~/Library/Caches/com.apple.finder/Finder.app/Contents/MacOS/19E17284, copies the real Finder icon, sets bundle id apple.finder.system with no Dock icon, opens it, and prints: "This package is incompatible with this version of macOS and may fail to install."

6. Layer 3: scouting

Rust, stripped, links SQLite. Its only raw socket connects to 127.0.0.1 on ports 19222 to 19321, and the code carries Chrome DevTools Protocol messages. That is the victim's own browser, not the server. The server address is not in the file as text.

7. Layer 3: forced execution

The arm64 half was mapped into the Unicorn emulator. Every system import became a stub that logs its arguments and returns. Single functions ran with dummy arguments and an instruction cap. 38 functions gave up 95 hidden strings in 7 seconds: the HTTP classes, a User-Agent template imitating Safari's network process, clipboard classes, a Monero address pattern, an alert that opens the Full Disk Access settings pane.

8. Layer 3: the locked configuration

Configuration sits in records of the form key : nonce : ciphertext. The record key is not the working key. The working key is derived from the record key, a 16-byte value and a 64-bit status, and the status is the XOR of eight values, one per anti-analysis check that passes.

So the malware never decides "I am being analysed". On an analysis machine the status is wrong, the cipher rejects the record, and it cannot read its own configuration.

Each value function was emulated alone. Of the 256 possible subsets of the eight values, the sample's own cipher accepted exactly one. With it, the records opened: the tag rocket, the upload address, an EVM wallet address and a 32-byte value. PyNaCl, given the captured working keys, returned the same plaintext for three of the four records.

Seen, inferred, unknown

Seen (in the code or the records) - The upload address, read by a function that calls the HTTP POST builder. - A Monero address pattern beside an embedded Monero address; an embedded EVM address. - Chrome DevTools Protocol messages and a local debugging-port connection; SQLite. - The eight checks in layer 1, the eight in layer 3, and the twelve-country lists.

Inferred (each from the evidence named) - It is an information stealer aimed at browser sessions. Capability is seen; use was not observed, because nothing ran. - It replaces copied wallet addresses with its own. No swap was observed. For the EVM address the matching pattern was not recovered. - One operator registered both domains. From timing and registrar. - The authors avoid victims in twelve post-Soviet countries. This indicates a milieu, not a person, and it can be imitated. - The decoy error exists to make the victim believe nothing was installed.

Unknown - Who operates it. The registrant is withheld and both domains sit behind Cloudflare. - The family name. No public source names this chain. - What the server answers. It was never contacted. - Whether the wallets have received funds. - The x86_64 half of layer 3 and a 56,240-byte block read by its main function.

What went wrong on the way

  • The embedded text was first treated as one encrypted record. It is four, packed end to end.
  • A sweep was reported as covering every function. It had covered about 1,200 of some 4,800.
  • For about 15 minutes the Rust Once states were read backwards, and eight constants were taken for check results.
  • Two key-guessing attempts failed (1,440 and 2,592 combinations of hardware values) before it was clear the status depends only on pass or fail.
  • Emulator fixes that cost time: the CPU model must be UC_CPU_ARM64_MAX (Rust uses LSE atomics); thread-local storage needs a stub; r2 aa alone finds about a quarter of the functions, aa; aac finds the rest.

If you saw this page

Did not paste: close the page. No real CAPTCHA asks you to open Terminal, Run or PowerShell.

Pasted and pressed Enter on a Mac: 1. Disconnect the Mac from the network. 2. Look for ~/Library/Caches/com.apple.finder/Finder.app. 3. From another device, sign out of every account everywhere, then change passwords, starting with email and banking. Signing out is what cancels a stolen session. 4. Move any crypto funds to a wallet created on a clean device. 5. Remove Full Disk Access from any unknown "Finder". Treat the Mac as compromised until it is rebuilt.

Limits of this result

  • Nothing ran, so capability is seen and use is inferred. No upload and no wallet swap was observed.
  • Only the arm64 half of layer 3 was analysed.
  • The lure page was never visited. It is known from a screenshot.
  • The EVM address is confirmed by the sample's own routine only, not by the independent check.
  • Two large threat-intelligence databases could not be read, so "not yet public" is a weak statement.
  • This is one case with one model. It shows this work went through; it is not a measured rate.

Rules kept

  • No layer was executed on any system.
  • No sample left the lab.
  • The upload address was never contacted.
  • Each widening of scope (capture, layer 3, deep analysis, emulation) had a human's word first. The AI did the work; a person gave permission at every step.
